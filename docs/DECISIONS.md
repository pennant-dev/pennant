# Decisions

Short records of choices that are not obvious from the code.

1. **System SQLite through a module map, no ORM.** Apple's SQLite ships FTS5 and the online backup API; the store is ~1500 lines of straightforward SQL. No third-party database dependency to keep in step with the MCP SDK's own dependencies.
2. **Network.framework for the API rather than a web framework.** `NWListener` speaks WebSocket natively, works on iOS for the client side, and avoids linking a second HTTP stack next to the MCP SDK's NIO. One port, one socket per client, text for JSON and binary for frames.
3. **Transient vs durable events.** Streaming deltas and status snapshots would flood the log and are always superseded by the next snapshot; everything that describes what happened is durable and replayable.
4. **Pause and cancel are Swift task cancellation.** The loop, inference stream, and shell processes all honour cancellation; a consequential tool interrupted mid-flight is recorded `uncertain` rather than guessed.
5. **Read-back rule is enforced by the runtime, not just prompted.** An identical consequential call after an uncertain outcome is refused until an observation tool succeeds. Prompts drift; records do not.
6. **Fresh-screen rule after interruptions only.** Requiring a screenshot after every click made the model take twice as many turns; requiring one after a wait, takeover, pause, resume, or restart covers the cases where the screen changed under the agent.
7. **Asserted beats inferred, and both are kept.** A conflicting inferred claim becomes `contradicted` next to the asserted fact so the Memory view can show the disagreement and the user can resolve it.
8. **Checkpoints mix model narrative with runtime facts.** The model writes the summary; the runtime appends outstanding tool outcomes and event ranges and strips "done" claims that reference unresolved tools.
9. **MCP tool names are prefixed with the server name.** Avoids collisions between servers and makes the source visible to the model and in tool records.
10. **The local Mac app trusts a 0600 token file; everyone else signs in.** Same-user loopback access does not need a ceremony; anything over the network does. Phones first paired with a six-digit code; accounts replaced that (a password, Microsoft, Google or GitHub, or an invite's one-time code), so each device holds a token of its own that removing the person revokes.
11. **The host runs unsandboxed and is installed as a LaunchAgent from the app bundle.** Broad machine access and TCC permissions need a stable signature and a process that outlives the window.
12. **A completion nudge for unbacked "remembered" claims.** Cheap to check against tool records, and it caught a small model's false claim during the first live run. It is a guard, not a substitute for a capable model.
13. **A light design system of its own.** Familiar interaction patterns (a sidebar of threads, dark user bubbles, a screen-and-routines inspector, colour dots) with Pennant's own palette, marks and icon. See docs/DESIGN.md.
14. **Choose before you type.** Every input that can be a menu, chip row, picker, or autocomplete is one; free text stays for names, prompts, and search. Avatars are stored as `shape:<name>` tokens so agents made by the model or the CLI land on the same visual system.
15. **A task limit is a checkpoint, not a failure.** The per-task allowance (steps, tokens, wall time) exists to catch runaway loops, but failing the task threw away good work. Reaching a limit now posts a note, waits in `waitingForUser`, and any reply grants the same allowance again. Defaults went from 60 steps / 400k tokens / 1 h to 200 / 5M / 4 h; zero disables a limit; configs still carrying the old numbers are upgraded on load.
16. **Compaction triggers on an absolute size, not only a window fraction.** With a 1M-token window, "75% of the window" meant 750k tokens of history before compaction, and long-context models drift long before that. `compaction.triggerTokens` (default 128k, adjustable in Settings, zero to disable) caps it; the fraction still applies for small windows.
17. **Markdown is rendered, not shown.** Agents write Markdown; the chat renders headings, lists, tables, quotes, and code blocks through MarkdownUI with a Pennant theme (a light one for agent bubbles, an inverted one for the black user bubble).
18. **Conversations live under the agent, not behind a toolbar button.** Double-clicking (or the hover chevron on) an agent row unfolds its recent conversations in the roster; the header caption is a menu too. The roster preview line is the latest message, which the host keeps on `Conversation.preview` so lists never need message pages.
19. **Deleting an agent deletes what only it owned.** Conversations, tasks and their records, artifacts, scheduled jobs, workers, and memories in its private scope go; shared memories and skills stay. Active tasks are cancelled and their cancellation persisted before rows are removed.
20. **Skill sources are remembered, and imports are chosen.** Folders and git checkouts persist as locations on the host; every import starts with a preview (new / updated / unchanged) and imports only what was ticked. Git URLs are cloned shallow under the data folder and pulled on the next preview.
21. **The host owns MCP sign-in; the app only opens the browser.** OAuth 2.1 with PKCE runs in `pennant-host`: metadata discovery, dynamic client registration, a loopback redirect listener, token exchange and refresh. Tokens and API keys live in the host Keychain (`dev.pennant.host.mcp`) and never appear in the config or on the wire except once, when a key is set. The Mac app opens the authorization URL; the iPhone hands that step to the Mac because the redirect lands on the host's loopback.
22. **A curated catalog with a `verified` flag, not a live registry.** Known servers ship as data in Core so a Connect button can build the config and start the right flow; entries checked against the publisher's docs are marked verified, the rest carry a docs link and a chip. Anyone can still add a custom server with any auth.
23. **Files from agents are artifacts with a `.file` message part.** `share_file` copies a file into the artifact store and posts it into the conversation; the client fetches bytes on demand and offers Save and Open. Bytes never sit in messages or in the model's context, which only sees `[shared file: name, size]`.
24. **Tool calls read as activities, not JSON.** One card per call, with its result folded in: a family symbol, a human title built from the key argument, a status chip, one summary line, and the raw input and output behind a disclosure. The wire format is unchanged; only the rendering pairs a call with its later result.
25. **The model is visible and switchable from the chat header.** The chip shows the host's current model and lists what the endpoint serves; picking one updates the host config, which the inference layer applies live. Per-agent models are a possible later step; today the model is host-wide.
26. **A ChatGPT account can be the inference provider, via the Codex OAuth route.** The ChatGPT desktop app exposes no local API; what Hermes and similar tools do is sign the account in with OpenAI's Codex OAuth flow (loopback port 1455) and call the ChatGPT backend's Responses endpoint that Codex clients use. Pennant does the same in the host, keeps the tokens in the Keychain, can reuse an existing Codex CLI login on request, and renders the choice as a provider switch in Settings. OpenAI's terms govern subscription use; the runbook says so plainly.
27. **One sign-in provider, ChatGPT; everyone else through API keys.** Google closed "Login with Google" for individuals on 2026-06-18 (Code Assist licences only) and Qwen shut its OAuth free tier on 2026-04-15, so those routes would serve almost nobody; both are covered by key presets (AI Studio, Alibaba Model Studio / Coding Plan) instead. A GitHub Copilot sign-in was built and removed before the first release: it needed another client's identity and an undocumented token exchange. Anthropic subscription sign-in is deliberately not offered; Anthropic's terms do not allow it from third-party apps, and its API works through the endpoint provider with a key. Claude Code coding runs are different: Pennant runs the `claude` program you installed and signed in to yourself, which Anthropic allows.
28. **Inference profiles live in the host config, and presets never carry personal endpoints.** A profile is an `Inference` (provider, endpoint, key, model, window) applied whole; the model pill lists profiles first and can save the running setup. The shipped preset catalogue is for public services only.
29. **Skills can be taught by demonstration, recorded as actions, not video.** Teach mode runs a listen-only event tap in `pennant-host` and names each click through Accessibility (the control under the pointer, or its enclosing button), merges typing per field, keeps shortcuts, app and window switches, and the user's notes. It skips the agent's synthetic input, Pennant's own windows, and password fields. The current model drafts a provisional skill from the trace (origin "taught"); the raw trace stays in the skill's instructions so the agent can see the exact labels. Positions are stored as fractions of the window only for controls Accessibility cannot name.
30. **Native connectors run in the host and look like MCP servers.** Microsoft 365 (Graph), LinkedIn and Reddit publish no MCP server a person can use without a partner programme or an aggregator, so Pennant calls their APIs itself with the user's own app registration. Each connector is served over the SDK's in-memory transport, so status, sign-in, tool registration and the Connections screen are shared with remote servers. Sign-in gained configured endpoints (`OAuthServerConfig`) for providers without discovery: optional PKCE (LinkedIn rejects it), no RFC 8707 `resource` for plain APIs, secret-in-body, Basic with an empty secret (Reddit installed apps), extra authorize parameters, token headers, and a `localhost` redirect host because Entra matches localhost redirects on host and path. Microsoft's Work IQ servers are catalogued too, for tenants with Copilot licences.
31. **Agents choose their model and effort; tools load on demand; replies that stop at an offer go back.** Each agent can run on a saved profile with its own reasoning effort (sent as `reasoning.effort` to ChatGPT and `reasoning_effort` to endpoints, where it also drops `temperature`, which reasoning models reject). A task moves to the host model, then the host's fallback profile, when a model refuses it (4xx), after retrying 429s with back-off. Connected services' tools no longer ride along on every turn (128 tools, ~45k tokens before): built-in tools stay, services are listed in the prompt and load through `find_tools`, by calling one of their tools, or per agent ("Always load"). A final reply that ends in an offer or a plan is sent back up to twice with an instruction to do the work, ask with ask_user, or finish; the runtime also picks up config changes live.
32. **The house rules are editable and every prompt is inspectable.** The "How to work" block moved out of code into `HouseRules.default` and `HostConfig.houseRules` (Settings › House rules, with a reset). The runtime keeps each agent's latest turn taken apart (system prompt by section, history, tool definitions, token estimates); "See what <agent> sees" in the agent's menu shows it, or a preview built the same way before the first turn. Each section says where it is edited.
33. **Pennant, and flags instead of faces.** The project was called Cove, then briefly Ayes, before it became Pennant (pennant.dev). Agents fly a flag with a symbol for their job instead of a face, and the mark is a pennant. The rename moved everything in one step: app and module names, the `pennant` and `pennant-host` binaries, bundle IDs (`dev.pennant.*`), the Bonjour type (`_pennant._tcp`), the sign-in link (`pennant://auth`) and the data folder (`~/Library/Application Support/Pennant`). Old names keep working: the first start moves the folder and leaves `Ayes` and `Cove` as links to it, Keychain secrets are read lazily under `dev.ayes.*` and then `io.cove.*` names (one prompt per secret at most, never at start), the iPhone reads its saved sign-in from the old Keychain service once, and the Mac app copies settings from `dev.ayes.mac` and `io.cove.mac`. The new bundle IDs are new apps to macOS, so Accessibility, Screen Recording and Full Disk Access are granted again. Laravel also has a package called Pennant (feature flags); different field, noted.
34. **One agent.** Several named agents with their own jobs (Inbox, Poster, Ops, Coder, the Steward…) made hand-offs lossy and roles confusing, so Pennant is the only agent you talk to. The old agents' jobs are skills on schedules, each run in its own thread; big jobs use task-scoped helpers; code changes are coding runs (`code`, set up in `HostConfig.coding`) in a thread under the one that asked; the health review is a daily job on Pennant (`pennant health enable`). The tools and commands for several agents (creating, asking and messaging other agents, deleting one) and the one-off migration that folded existing agents into one were removed before the public release; agents retired by it still load. Supersedes the roster in #18.
35. **A Pennant engine next to Claude Code.** Coding runs only drove the Claude Code CLI, so the models you set up in Settings › Models couldn't write code. The Pennant engine runs a coding run on Pennant's own task loop instead, on a model you choose, with five tools scoped to the project folder (`read_file`, `list_directory`, `edit_file`, `write_file`, `shell`) and the same asking rules as Claude Code runs (its calls go through `coderPermission` as Bash, Write and Edit). Claude Code stays for those who have it: it is the stronger coder. Coding also gained several named project folders and settings you can edit in the app. The other engine the settings offered, a second coding CLI that never ran, was dropped rather than built: two ways to write code are enough.
36. **Pennant works beside the owner, not on their screen.**
    - **Why.** Driving the Mac through the real pointer meant the owner couldn't use it while Pennant worked. Touching the mouse paused the work.
    - **Web.** Pennant now works on the web in tabs of its own in the owner's Chrome, through an extension. The extension uses Chrome's debugger input, so clicks and keys go to the page and not the OS. It's an extension, not a Playwright browser, because Playwright runs in a profile of its own and the owner's sign-ins are the point.
    - **Mac apps.** Pennant works in Mac apps in the background, through Accessibility actions and events posted to the app's process.
    - **Its own cursor.** An overlay shows where Pennant is working, above every window, and agent screenshots leave it out.
    - **Order.** The prompt tells threads to try the Chrome tabs first, then apps in the background. The owner's pointer and screen come last.
    - **Sites.** Pennant uses any site; a card before a site's first use is a setting, off by default, because asking on every new site was more friction than protection. Sending, publishing, deleting and paying still stop for the owner. The extension holds no secrets and talks only to the host on loopback, which accepts only its origin.
37. **Talk mode speaks with a local neural voice on the Mac.**
    - **Why.** Even Siri's voices sounded robotic to the owner. A realtime voice from a cloud provider would send every reply to that provider and tie Talk mode to it.
    - **What.** Kokoro-82M is the default: Apache 2.0, natural, and fast enough to say a sentence in a tenth of a second on Apple silicon. Qwen3-TTS 1.7B is there for more expression, at thirteen times the download. It's the same model the video narration used, so one copy serves both.
    - **Penny.** A woman's voice with an English accent comes from cloning a short recording that ships with the app. Qwen's own female speakers are native Chinese speakers. The 0.6B model clones in real time; the 1.7B doesn't. Each piece she says is a fresh copy of the recording's voice, and copies differ a little (deeper, brighter), so a reply goes to her whole, in one piece. A clone can also run on past its words with laughter or background voices; the helper ends a piece at the first quiet moment past its words' length. A fixed random seed was tried and dropped: it made such a take happen every time for the same text.
    - **One engine for speech.** Skills that narrate call the helper from the command line (`speak`, `transcribe`), not a Python setup of their own.
    - **How it runs.** The model runs in a helper app, not in Pennant itself. A fault in it can't take the app down, its memory goes when Talk mode ends, it can be arm64-only while the app stays universal, and MLX stays out of the SwiftPM build and tests.
    - **Downloads.** The app downloads the models at pinned commits and shows the progress. The helper never goes to the network.
    - **The iPhone.** The phone doesn't run a model. It asks the host for each sentence and plays the audio as it streams back. Talk mode on the phone already needs the Mac, so this adds no dependency. The phone gets every voice the Mac has, including Penny and the 1.7B model it couldn't hold, with no download and nothing for its battery to do.
    - **Elsewhere.** Intel Macs keep the system's voices.
38. **Fewer sign-off cards for deleting.** Four to six delete cards a job were mostly clean-up.
    - **Why.** Of the six cards on 2026-10-04, four were for temporary folders the rule couldn't see were temporary. Each was a `/tmp` path held in a variable, a `mktemp` folder, or a `/tmp` checkout reached with `cd`.
    - **Temporary folders.** The rule follows a command's variables, `$(mktemp)` and `cd`, so deleting or discarding git changes inside a temporary folder needs no card.
    - **Allow deletes here for this thread.** A card whose deletes are paths has a second button. It approves this one, and later deletes in the same place in that thread go ahead: files in the same folder, anything inside a folder it removed, or the same checkout.
    - **What still asks.** Elsewhere, and anything that isn't a path (branches, cloud resources, records), still asks every time. Plain Approve still runs exactly what the card shows.
39. **A model is called by what it runs.** A profile's name was typed in and kept apart from its settings.
    - **What went wrong.** The Models page sent its own copy of the settings with each change. Two changes in quick succession sent a new default (DeepSeek) along with the previous model's settings (a small local model). The host took that for an edit of the default model and copied the small model into the DeepSeek profile, under DeepSeek's name. Every turn labelled DeepSeek ran the small model, and switching to "the better model" changed nothing.
    - **Names.** A profile's name is now worked out from its settings: the model as its provider names it, where it runs, and its effort when set ("DeepSeek-V4.1-Flash · Azure my-ai-resource · medium"). It's still sent for older apps, and matching by name also matches the provider's model name ("gpt-6-sol").
    - **Write-back.** The host no longer copies an `inference` edited on its own into the default profile. `inference` always follows the default profile.

40. **What the heartbeat does beyond Pennant's own work is the owner's words.** 0.3.0 had each beat list new unread mail through the Microsoft 365 connector, on by default.
    - **Why it changed.** That assumed one owner's setup. Another owner may use Gmail, Yahoo or no mail at all, and may want something else looked at entirely. A connector chosen for them in code, switched on by default, read their mail without their asking.
    - **Now.** Settings › Pennant › Heartbeat has "On each check-in, also", free text (`HostConfig.Heartbeat.instructions`, `pennant heartbeat also <text>`), empty by default. Whatever is written there is a turn of Pennant's on every beat, done with the tools and connections it has, and it's told how often it checks in and when it last did. With nothing written, a beat still makes no model call unless Pennant's own work needs a look.
    - **The cost.** A check-in with something written is a model call every beat (up to the daily cap), where the mail check read the mailbox without the model. Being right for every owner is worth more than that saving.

41. **Claude Code's skills are linked, not copied, and run where they can.** Owners who live in Claude Code already have skills and plugins there, and want Pennant to run them from the app.
    - **Linked.** Importing copies a skill once; the copy drifts the first time the owner edits it in Claude Code. A link re-reads `~/.claude/skills` and the enabled plugins' skills (as each plugin's manifest declares them) on start, on listing and every five minutes. Edits become versions, and removed skills go. The skills are read-only here, so there's one place to edit them. It's off by default: another owner's Claude Code folder isn't Pennant's to read until they say so.
    - **Run here when possible.** Most skills are instructions and scripts, which Pennant can follow on any model, the local ones included, at no cost to the owner's Claude plan. Those that rely on Claude Code itself (subagents, a forked context, hooks, `!` commands) are marked and handed to a Claude Code run through the existing coding path. Nothing is lost in translation, and the run's permission requests still come to Pennant as cards.
    - **Names.** Pennant finds skills by name, so a Claude Code skill whose name one of Pennant's own skills already has is left out and logged, rather than becoming a surprise new version of it. Plugin skills keep Claude Code's `plugin:skill` names, which don't clash.
    - **No new tool.** `use_skill` does the hand-off (with an optional `request`), so the model's tool list doesn't grow.
